Automated 5-Stage Release Engine

An industrial-grade, secure, and reproducible build pipeline running on native ARM64 silicon.

01

Upstream Semver Tag Synchronizer

GitHub Actions webhook monitors anza-xyz/agave for new production tags (e.g. v1.18.26, v4.2.2). Builds trigger within 60 minutes of upstream release dispatch.

02

Bare-Metal Native ARM64 Runners

Compilation executes on dedicated AWS Graviton instances (c7g.4xlarge) and bare-metal ARM64 machines, ensuring bit-for-bit instruction fidelity without QEMU emulation overhead.

03

Automated AST & GCC 15 Transitive Header Patch Engine

Applies automated patchsets across 290+ RocksDB C++ headers to guarantee full forward compatibility with GCC 14/15 and Clang 20 toolchains while maintaining Rust FFI link integrity.

04

Verification & ELF64 Packaging

Compiles all 24 binaries via cargo-install-all.sh, audits dynamic ELF linkage against glibc 2.31+ baseline, and packages into a compressed .tar.bz2 distribution bundle.

05

Cryptographic Signing & SLSA Provenance Attestation

Generates SHA256 checksums, Minisign/GPG signatures, and SLSA Level-3 build provenance attestations before publishing to GitHub Releases CDN and universal install endpoints.

Devlog #01: LiteSVM + Anchor on aarch64 Linux

If you are a Solana developer working on an ARM64 (aarch64) Linux machine (like Fedora Asahi on Apple Silicon), you've likely encountered serious friction. The standard solana-test-validator is heavy, and pre-built binaries don't support aarch64 Linux out-of-the-box.

The Goal: LiteSVM + Anchor

LiteSVM (by OtterSec) bypasses the heavy local validator to run smart contract tests purely in a simulated, native Rust environment, executing transactions in fractions of a second.

Challenge 1: Dependency Conflicts

litesvm 0.6 pulls Solana v2/v3 types, while Anchor v0.30.1 pulls v1/v2 types, leading to trait resolution conflicts.
The Fix: Pinned explicit Solana crates (solana-keypair, solana-pubkey, solana-sdk, solana-program) to ~2.0 to align perfectly with the LiteSVM 0.6 environment.

Challenge 2: The aarch64 Toolchain Nightmare

Running cargo build-sbf attempts to fetch a 504MB pre-built archive that routinely corrupts on drops.
The Ultimate Fix: We compiled the Solana SBF toolchain locally, pre-fetching dependencies, patching librocksdb-sys GCC 15 headers, and producing a native toolchain that builds counter.so in 18 seconds!

Challenge 3: Matching Contexts in LiteSVM

Raw LiteSVM instructions require passing exactly the signer accounts the Anchor contract expects: 

let inc_ix = Instruction {
    program_id: program_id(),
    accounts: vec![
        AccountMeta::new(counter_pubkey, false),
        AccountMeta::new_readonly(payer_pubkey, true), // authority signer
    ],
    data: increment_discriminator().to_vec(),
};
