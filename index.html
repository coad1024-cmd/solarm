System Architecture

Automated 5-Stage Release Engine

An industrial-grade, secure, and reproducible build pipeline running on native ARM64 silicon.

01

Upstream Semver Tag Synchronizer

GitHub Actions webhook monitors anza-xyz/agave for new production tags (e.g. v1.18.26, v4.2.2). Builds trigger within 60 minutes of upstream release dispatch.

02

Bare-Metal Native ARM64 Runners

Compilation executes on dedicated AWS Graviton instances (c7g.4xlarge) and bare-metal ARM64 machines, ensuring bit-for-bit instruction fidelity without QEMU emulation overhead.

03

Automated AST & GCC 15 Transitive Header Patch Engine

Applies automated patchsets across 290+ RocksDB C++ headers to guarantee full forward compatibility with GCC 14/15 and Clang 20 toolchains while maintaining Rust FFI link integrity.

04

Verification & ELF64 Packaging

Compiles all 24 binaries via cargo-install-all.sh, audits dynamic ELF linkage against glibc 2.31+ baseline, and packages into a compressed .tar.bz2 distribution bundle.

05

Cryptographic Signing & SLSA Provenance Attestation

Generates SHA256 checksums, Minisign/GPG signatures, and SLSA Level-3 build provenance attestations before publishing to GitHub Releases CDN and universal install endpoints.

Ultra-Fast Testing

LiteSVM + Anchor on ARM64 Linux

Experience sub-second smart contract testing without running heavy validator daemons.

1. Compile with Native SBF Toolchain

Compile your Anchor program directly to a native SBF shared object (.so) using our ARM64 toolchain: 

cargo build-sbf --manifest-path programs/counter/Cargo.toml

2. Load & Execute in Memory (0.15s)

LiteSVM loads the .so bytecode and executes instructions in fractions of a second: 

let mut svm = LiteSVM::new();
svm.add_program(program_id(), include_bytes!("../counter.so"));
let res = svm.send_transaction(tx);
assert!(res.is_ok()); // Done in 150ms!

Solana Foundation Grant Proposal Dossier

Executive Summary

In the current Solana/Agave release infrastructure, pre-compiled release binaries exist only for x86_64-unknown-linux-gnu, aarch64-apple-darwin (macOS), and Windows. Linux ARM64 is completely absent.

Whenever developers launch AWS Graviton instances, Oracle Cloud Ampere A1 servers, Raspberry Pi 5 clusters, or Apple Silicon machines running Linux (Asahi), the official installer fails immediately with a 404 Not Found error. Developers are forced to spend 45 to 90 minutes compiling from source.

Proof of Work & Verification

Unlike theoretical proposals, SolARM has already built, tested, and packaged the entire 24-binary release suite (209 MB) on bare-metal physical ARM64 Linux hardware. The solution eliminates GCC 15 transitive header conflicts in librocksdb-sys and provides bit-for-bit verified ELF 64-bit executables.
